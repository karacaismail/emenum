What was implemented:
- Fixed critical bug in auto-dismiss timer implementation
- Replaced useEffect-based timer recreation with useRef-based timer tracking
- Each toast now maintains its own individual timer from creation
- Timer management using Map<string, NodeJS.Timeout> stored in useRef
- Proper timer cleanup in multiple scenarios:
  * removeToast() - clears timer when toast manually dismissed
  * Queue overflow - clears timers for toasts removed due to MAX_TOASTS limit
  * clearAllToasts() - clears all timers when all toasts removed
  * Component unmount - cleanup effect clears all timers to prevent memory leaks
- Reorganized function order to fix dependency issues (removeToast before showToast)
- Added useRef import to React imports

Bug Fixed:
The original implementation recreated ALL timers whenever the toasts array changed:
- When toast A was created with 4-second timer
- After 2 seconds, toast B added would trigger useEffect again
- This cleared toast A's timer and created a new 4-second timer
- Result: toast A would dismiss 4s after B was added, not 4s from its own creation
- New implementation: each toast gets one timer on creation, never reset

Files modified:
- components/providers/toast-provider.tsx (updated)

Implementation details:
1. Added timersRef using useRef<Map<string, NodeJS.Timeout>>
2. In showToast():
   - Timer created immediately after toast added to state
   - Timer stored in Map with toast ID as key
   - When MAX_TOASTS exceeded, timers for removed toasts cleared
3. In removeToast():
   - Timer cleared from Map before removing toast from state
4. In clearAllToasts():
   - All timers cleared from Map before clearing toast state
5. Added useEffect for component unmount cleanup
